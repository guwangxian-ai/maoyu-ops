## 完成的能力

- **自助注册与邮件验证码**：注册、发送注册邮件、校验注册验证码共用服务端开关；缺失默认关闭，读取异常不冒充管理员关闭。验证码发送中不可使用，失败/取消仅撤销本次记录，发送成功后开始有效期，公共校验也执行类型和五次错误上限。验证码使用标准库 `secrets` 生成。注册页处理加载、关闭和读取失败，支持重试，登录页在确认开放后显示注册入口。
- **通知事件订阅**：账号绑定和通知渠道均可选择聊天、发货相关异常、账号状态；两级取交集，历史空值兼容全开。旧客户端只切换绑定启用状态时保留原类型。网页开关增加键盘语义；本轮没有替用户改变生产通知配置。
- **商品查询与卡券选择**：商品管理分页合并配置状态查询，保留用户/账号范围、完整详情搜索、默认回复、卡券状态以及本项目的在售快照和时间字段。卡券选择使用名称/ID轻量分页、显式查询和过期响应隔离，读取既有绑定失败时禁止保存，保留孤立关联。正在查询时可提交不同关键词，同词重复请求仍受保护；手机采用上下分区，桌面并排显示。
- **公共单品发布模块**：账号能力检测、载荷、快照、鱼小铺/普通卖家发布和所在地查询迁入 `common`，旧 `app.services` 路径保留兼容导出。Scheduler 不再为这些单品入口按路径加载网页后端或修改其 `app` 包路径。保留本项目不可信能力检测的发布拒绝、库存 0 和最大库存行为。所在地传输沿用有界重试和取消清理，日志不保存请求头、查询密钥或完整响应。

## 迁移与依赖

- 旧消息通知表幂等补齐 `notify_types`，历史记录默认全部事件，不删除绑定。
- 在原启动数据库自检锁内补齐商品查询索引；多个缺失索引合并为一次在线 ALTER，显式要求 `ALGORITHM=INPLACE, LOCK=NONE`。不支持或现有同名索引不兼容时明确失败，不退回锁表复制。实际大表建索引仍消耗磁盘/CPU，并可能等待短暂元数据锁，上线需核对当前数据量和可用空间。
- 默认设置补齐使用保存点。真实 MySQL 并发测试发现普通重查仍可能读取旧快照，已改为在冲突后用锁定读确认并发创建的值，提交后重新查询；不覆盖管理员已有设置。相关隔离语义见 [MySQL 官方文档](https://dev.mysql.com/doc/refman/8.0/en/innodb-consistent-read.html)。
- Scheduler 依赖声明补充后端已有的 `pycryptodome>=3.19.0`、`opencv-python-headless>=4.10.0`，用于既有媒体模块；本轮验证复用现有镜像，没有安装全局依赖、引入付费 API 或创建收费资源。
