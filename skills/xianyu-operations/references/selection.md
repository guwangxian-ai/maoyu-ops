# 选品

目标是找到值得小规模验证、能够真实交付的商品，不把搜索排名或“想要”当作销量。

用户查询“我账号里的某个商品/当前价格/是否在售”时，转到 [账号商品同步与查询](catalog-sync.md)。本节的市场搜索不能代替本人商品同步，也不能把竞品搜索结果当成用户已上架的商品。

1. 从当前项目和用户资料了解可交付内容、授权来源、时间与预算。已有经营方向就沿用；信息不足时选一个低成本可验证假设，不假设用户有客户或现成素材。
2. 读取 `search_search_items` schema，以具体关键词搜索，保存关键词、时间、页码和真实返回。输入示例：`{"body":{"keyword":"Excel 模板","page":1,"page_size":10}}`。当前搜索使用本站用户自己的第一个 active 账号；多账号时不能声称已按指定账号搜索，若身份选择影响结果需先处理这个限制。
3. 检查是否真实返回列表。登录失败、缺少浏览器依赖、超时、风控或 `verification_required` 是执行阻塞，不能解释为“市场无需求”。平台验证由用户完成；已有有效搜索结果可先用于研究，注明来源和时间。
4. 去重商品 ID，检查返回的价格、标题、规格、地区、发布时间、`want_count`、来源链接。缺失值标为未知；`want_count` 的默认 0 也可能是字段未解析，不能证明无人关注。搜索只是一页样本，不能声称全市场统计。
5. 推荐至多三个候选，优先推荐一个：明确买家问题、交付内容、竞品差异、资料版权、成本/售后风险、最便宜的需求验证办法。引用真实 item_id/来源链接，不复制竞品文案、图片或付费资料。

保存候选结构可包括：

```json
{
  "keyword": "Excel 模板",
  "evidence": [{"item_id": "来自搜索结果", "source_url": "来自搜索结果", "checked_at": "实际时间"}],
  "customer_problem": "待核实的具体问题",
  "deliverable": "能自行制作或已获许可的内容",
  "source_rights": "待核实",
  "price_observations": [],
  "cost_known": false,
  "validation": "先完善一份可用样例和一条获准的商品草稿"
}
```

利润测算仅对有来源的数字计算：售价 − 已知直接成本 − 平台费用 − 预计退款/售后成本；缺一项就标为估算/未知，不给收益保证。不要为收集数据下单、联系卖家或开付费服务，除非任务已有授权。

验收是“候选有证据、可交付性可解释、下一步可执行”；只有业务授权范围内才进入上架。若搜索被平台阻塞，交付研究草稿和阻塞证据，不能冒充已完成真实选品。
